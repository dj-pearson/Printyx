### SEC-001: SQL Injection in storage.ts getBusinessRecords() - FIXED
**Vulnerability**: String interpolation in raw SQL (conditions.push(`record_type = '${recordType}'`)) + sql.raw(whereClause)
**Fix**: Replaced all string interpolation with Drizzle ORM parameterized queries (eq(), or(), sql template with bindings, .limit()). Added bounds checking on limit parameter (capped at 500).
**Files Modified**: server/storage.ts

### SEC-002: SQL Injection in routes-custom-reports.ts last_n_days filter - FIXED
**Vulnerability**: sql.raw(filter.value) inside INTERVAL clause allowed SQL injection via request body
**Fix**: Replaced with parseInt() validation + parameterized interval multiplication. Rejects non-numeric and out-of-range values (0-3650).
**Files Modified**: server/routes-custom-reports.ts

### SEC-003: XSS in email-templates.ts via unescaped user data - FIXED
**Vulnerability**: User-controlled data (userName, userEmail, trialDays, trialEndDate) interpolated directly into HTML email templates without escaping
**Fix**: Added escapeHtml() utility that encodes &, <, >, ", ' to HTML entities. Applied to all user data in all HTML templates. Added encodeURIComponent() for tokens in URLs.
**Files Modified**: server/services/email-templates.ts

ABK-001 used `uuid` for tenant_id which is a type mismatch with the actual tenants table — I deliberately did not repeat that mistake.

**Index hot paths** (from PRD AC):
- `blog_posts(tenant_id, status, published_at)` ✅
- `blog_keywords(tenant_id, cluster_id)` ✅
- `blog_distributions(post_id, platform)` ✅
- `blog_refresh_queue(tenant_id, scheduled_at)` ✅

Plus per-table tenant index, status indexes where filtering is common, and target/post indexes for FK-heavy lookups.

**Soft delete vs hard delete**: User-facing entities (brand voices, style guides, clusters, briefs, assets, posts, distribution targets) get `deleted_at`. Derived/log tables (revisions, citations, performance metrics, refresh queue, audit log) hard-delete via FK CASCADE — a deleted post takes its revisions and citations with it.

**RLS pattern**: Calls `apply_tenant_rls(table_name)` from `drizzle/rls/apply-rls.sql`. The function introspects `tenant_id` column type (uuid vs varchar) and casts the JWT claim accordingly. All 14 blog tables use varchar `tenant_id` so the JWT comparison is direct text equality. Policies enforce `tenant_id = (auth.jwt() -> 'app_metadata' ->> 'tenantId')` for SELECT, INSERT (WITH CHECK), UPDATE (USING + WITH CHECK to prevent re-parenting), and DELETE.

**Zod schemas**: every table gets a `createInsertSchema(table)` with explicit enum constraints on status/type fields. Edge functions in US-BLOG-013 (CRUD) onward should import these.

### Append-Only Semantics
The standard tenant RLS pattern installs SELECT/INSERT/UPDATE/DELETE policies. For the audit log we want INSERT + SELECT only — UPDATE and DELETE policies are dropped after `apply_tenant_rls()` runs, and table-level GRANTs are revoked too. Two layers of defense:
1. RLS policy: no policy = no row matches = silent empty result on UPDATE/DELETE
2. Table GRANT: missing privilege = explicit 403 from PostgREST

Service role (used by edge functions via `createSupabaseServiceClient`) bypasses RLS entirely so `writeAuditLog` continues to work. End-users go through the anon/authenticated client and hit the wall.

### What Shipped

**Edge Function** — `supabase/functions/blog-post-revisions/index.ts`
- `GET /blog-post-revisions?post_id=&limit=&offset=` — list newest-first; validates parent post belongs to tenant before exposing rows
- `GET /blog-post-revisions/:id` — fetch one full revision (body included)
- `POST /blog-post-revisions` — create a revision; computes `revision_number = max+1`; **dedupes** when title + body_markdown + body_html + meta_title + meta_description are byte-identical to the latest (prevents autosave from spamming the table on no-op edits — returns `{ deduped: true }` on the dedup path)
- `POST /blog-post-revisions/:id/restore` — atomic 2-step: snapshot post → apply revision content to post → stamp a new revision tagged `manual` with `diff_summary: 'Restored from #N'`
- `POST /blog-post-revisions/cleanup` — purges rows older than `blog_agent_settings.revision_retention_days` for the tenant; **always preserves the latest revision per post** so we never fully orphan a post's history. Cron-friendly.
- All mutating actions write to `blog_audit_log` via the centralized `writeAuditLog` + `withRequestContext` helpers
- Permission gate: `blog.post.edit` (platform admin OR users with the perm)
- Tenant isolation: every query filters by `tenant_id`; revision rows have a denormalized `tenant_id` column on insert
- Auto-discovered by `supabase/functions/server.ts` — no proxy table edit needed

**Editor autosave** — `client/src/pages/platform-admin/blog/BlogPostEditor.tsx`

- Client-side dedup signature (cheap concat of title + bodies + meta) skips scheduling a save when nothing changed; server-side dedup is the ultimate guard
- Hydrates the dedup signature at load time so re-opening a post never triggers a phantom autosave

- Per-job: call HANDLERS[type] → on success: status=completed, result=blob, attempts++, audit `blog_job.complete`
- Per-job: on throw: compute next backoff (attempt 1→+1m, 2→+5m, 3→+30m, 4→+2h, 5→permanent fail). status flips back to queued (rescheduled) or final 'failed'. Audit `blog_job.fail_retry` or `blog_job.fail_permanent` with full stack.

**Operations:**
